Ingestion layer, in order of ROI

Five ways stock reaches the ledger. Each card is honest about whether it's a real integration or a stand-in for hardware / a model call not wired up yet.

Real

Excel / CSV

A rule-based mapper proposes column matches and unit conversion (kg/g, L/ml). Confirm once — the mapping is remembered by header signature and later files with the same columns import automatically.

Simulated

Photos — invoices, GRNs, batch sheets

A photo returns a placeholder JSON extraction in the shape a real vision API would return, for review against the PO before it's saved. No vision model is connected in this build.

Real

Barcode / QR labels

The browser's native camera scanner reads a batch label and jumps straight to its trace record. Falls back to manual entry where the browser doesn't support it.

Simulated

Weighing

No scale hardware here — a simulated live reading stands in. The endpoint it posts to is exactly what a real ESP32 (serial/Bluetooth → HTTP) would call, so real hardware drops in without touching the rest of the app.

Not built

Tally XML export

Most Indian SMEs run Tally, but the exact XML schema needs verifying against your version before claiming support — so it isn't built rather than guessed at.

Core design

01

Event-sourced stock ledger

Every ingest — manual, CSV, photo, scan or scale — is written as an event with its source, a confidence score and an approver. Lots, batches and shipments are just the current state read off that log, so traceability, recall and audit are the same log, not separate features.

02

FEFO, not FIFO

Production draws ingredients from released stock in soonest-expiry-first order, automatically, across as many lots as a batch needs.

03

Forecast → reorder

A simplified linear-trend model (not Prophet/statsmodels — that's a second Python service the demo intentionally skips) feeds forecast × BOM − stock − open POs. Backtest error is shown honestly, small samples included.

Single Node.js/Express service exposing a JSON REST API (/api/lots, /api/batches, /api/trace/:id, /api/forecast/:product…), deployed to the cloud on Render. Data currently lives in memory — see the README for the PostgreSQL upgrade path.
